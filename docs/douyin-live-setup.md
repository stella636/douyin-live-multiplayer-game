# 抖音直播间搭建与接入要求

> 本文档基于抖音开放平台公开文档整理，供本项目从「本地 H5 原型」走向「真实直播间上线」时参考。

## 一、先选路线

抖音直播互动大致有两条路，技术形态不同：

| 路线 | 形态 | 适合本项目吗 |
|------|------|-------------|
| **弹幕小玩法** | 主播端 `exe` 客户端 + 开发者后端收礼物/评论/点赞 | 适合全屏玩法、PC 直播伴侣 |
| **互动工具（互动插件）** | 半屏小程序面板 + Canvas 玩法卡片 | **更适合竖屏、手指钢琴式条带玩法** |

当前仓库的竖屏布局（上摄像头 / 中游戏条 / 下弹幕礼物区）更接近 **互动工具玩法卡片** 的产品形态。

官方文档：
- [创建直播玩法](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/toybox-start)
- [互动工具接入指南](https://partner.open-douyin.com/docs/resource/zh-CN/live-interactive-tools/introduction/interactive-tools-guide)
- [互动工具开发者指南](https://developer.open-douyin.com/docs/resource/zh-CN/live-interactive-tools/development/tutorial/app-interaction-guide)
- [弹幕玩法接入指南（抖音云）](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/develop/douyincloud/guide)

## 二、准入与审核要求

### 1. 入驻与创建项目
1. 在 [抖音开放平台](https://developer.open-douyin.com/) 完成开发者入驻
2. 创建对应玩法/互动工具项目，获得 **AppID**
3. 提交 **创意提案**（含 Demo 视频），评估通过后才能正式接入

### 2. 资质
- 个人/企业开发者均可提案
- 需要 **软著**（名称需与玩法名称一致；不能是 APP 或游戏类软著）
- 使用第三方 IP 需提供授权

### 3. 玩法不属于游戏备案范畴
- 直播小玩法/互动工具按平台规则走玩法审核，不要求小游戏备案

### 4. 后台需配置的内容
- 玩法名称、图标、介绍、开播文档
- **礼物效果**：如 `玫瑰 x1 → 生成跳板`
- **评论/点赞效果**：如 `跳 → 角色跳跃`（若支持）
- 规则介绍、排名/积分逻辑
- 直播间互动数据能力（礼物、评论、点赞推送）

## 三、技术架构要求

### 路线 A：弹幕小玩法（exe）
```
抖音直播间
    ↓ 礼物/评论/点赞
开发者后端服务（HTTP 回调 + OpenAPI）
    ↓ WebSocket
主播弹幕玩法客户端（exe，自选引擎）
```

要点：
- 主包体是可运行的 **exe**
- 后端至少 1 个专职服务接收平台推送
- 推荐使用抖音云降低长连接运维成本
- H5 规则页可用平台开发者工具（兼容 Cocos/Laya/白鹭）

### 路线 B：互动工具（推荐当前原型演进）
```
抖音 App / 直播伴侣
    ↓
互动插件玩法面板（半屏小程序 Page）
    ↓ tt.createLiveCard
互动插件玩法卡片（Canvas Card）
    ↓ 订阅开放数据
礼物 / 评论 / 点赞 → 玩法逻辑
```

要点：
- 需下载 **抖音开发者工具 IDE**
- 玩法卡片是 Canvas，需用 `tt.getLiveRoomCardInfo` 获取 **卡片最大宽高**
- 基础库建议 **3.41.0+**
- 一个小程序内同时只能打开 **一个** 玩法卡片

## 四、直播间 UI 布局要求（本项目已对齐）

真实直播间底部固定有 **弹幕、礼物、互动按钮**，因此：

### 不要做
- 横屏全屏盖住底部 UI
- 把核心操作区放在屏幕最底部

### 建议做（当前原型布局）
```
┌─────────────────┐
│   主播摄像头     │  50%  可见、可识别跳跃
├─────────────────┤
│ 冒险岛闯关条     │  35%  手指钢琴式可玩区
├─────────────────┤
│ 弹幕 / 礼物区    │  15%  预留给平台 UI
└─────────────────┘
```

对应文件：
- `packages/client/index.html` — 竖屏壳层
- `packages/shared/src/runner.ts` — `LIVE_LAYOUT` 比例配置

上线到抖音时，应改为读取 `tt.getLiveRoomCardInfo` 动态适配卡片尺寸，而不是写死 430×932。

## 五、开放数据能力

互动工具卡片开启后可申请：

| 类型 | 示例 | 本项目映射 |
|------|------|-----------|
| 礼物消息 | 玫瑰、小心心、钻石 | 架桥、护盾、加速 |
| 评论消息 | 观众发弹幕 | 后续可做「跳」「冲」指令 |
| 点赞消息 | 点赞 burst | 后续可做加速/回血 |

当前仓库已在 `packages/server/src/live/` 做了 **礼物事件归一化**，本地用 `/api/mock-gift` 模拟。上线时把抖音推送解析成同一 `gift.received` 结构即可。

## 六、从本仓库到上线的建议步骤

1. **继续在本分支打磨竖屏闯关 MVP**（当前 `feature/runner-mvp`）
2. **提案阶段**：录制 30~60 秒 Demo（竖屏、摄像头跳跃、礼物架桥）
3. **选择互动工具路线**，用抖音 IDE 新建互动插件项目
4. **把 Phaser 游戏迁入玩法卡片 Canvas**（或用 Cocos 重写渲染层）
5. **后端部署**，配置直播间数据推送回调
6. **真机联调**：直播伴侣 + 指定版本抖音包
7. **提交审核**，补充礼物/评论效果说明

## 八、FAQ 摘要

- **个人能做吗？** 可以，提案通过即可
- **必须用抖音云吗？** 不必须，但推荐
- **引擎有限制吗？** exe 路线自选；互动工具卡片需适配 Canvas/小程序环境
- **Demo 要求？** 需展示美术品质与核心玩法，平台会拦截质量明显不达标方案
